# G4 人工基线与七天试用记录协议（COL-24）

本页是空白记录协议，不含个人任务、真实使用数据或验收结果。G4 衡量单人日常使用；软件测试、G3 模型场景和 Notion 同步测试不能替代它。原始记录由试用者保存在私有位置，仓库只提交去标识汇总及证据索引，不提交任务标题、凭据或完整日记。

## 开始前固定

在 COL-24 写明协议版本、时区、人工基线起止日、试用起止日、候选 Git SHA、Web/API 版本、provider/模型与提示词/schema 版本、Notion 连接范围，以及记录人。人工基线可在工程准备期间采集，真实七天试用须在 G3 决策和对应候选版本确定后开始。升级或修复时记录日期、变更和受影响天数；变更前后的天数分段报告，不能直接拼成同一固定版本的七天结果。

没有历史实测时，先连续记录至少 **3 个自然日** 的人工规划基线。随后按同一计时和评分方法记录 **7 个连续自然日** 的 Agent 试用。缺席、忘记计时或当天结果未知时明确填“未知”；不能从当前任务状态倒推旧日数据，也不能把缺日默认为成功。若七天窗口缺少必需记录，应重新确定完整窗口并保留原始缺口。

## 每天怎样记

两阶段都从“开始决定今天重点”启动计时，到“最终确认今天重点集合”停止；记录实际用时秒数和中断秒数，中断不计入规划用时。若没有确认集合，就记“未闭环”和实际已耗时间，不能记零秒。当天开始时记重要事项及预期推进，日末由试用者给实际推进打 0/1/2 分：0 为未推进，1 为部分推进，2 为明确推进；简要写下依据。评分标准在两阶段保持一致。

每个自然日复制以下空白模板，保存在私有记录中：

```text
日期与时区：
阶段：人工基线 / Agent 试用
候选 Git SHA、provider/模型、提示词/schema（人工基线填不适用）：
开始前预计最重要的事项（可用私有代号）：
规划用时秒数：
中断秒数：
是否确认了当天重点集合：是 / 否 / 未知
Agent 建议：采纳 / 修改 / 拒绝 / 未生成 / 不适用
采纳后修改次数及原因：
重复录入或额外维护耗时秒数：
日末重要事项推进评分 0/1/2/未知，与简要依据：
错误或未经确认的业务变更次数、证据与恢复结果：
Notion 同步异常、可见状态、恢复耗时（无连接填不适用）：
无效打扰次数及原因：
阻塞、缺失字段或版本变更：
记录人和记录时间：
```

错误或未经确认变更即使已恢复，也计入事件数，并保留当时版本、时间、操作和结果。Agent 建议被宿主拦截与实际发生的错误变更分开记录。Notion 故障需区分网络/权限/未知结果与已证实的数据错误；不能把没有成功同步写成“当天没有外部任务”。

## 汇总判定

先确认原始记录的日期、版本和缺失情况，再计算。基线与试用的规划用时分别取每日实测中位数；默认目标是试用中位数比人工基线下降至少 **20%**。日末推进评分分别取中位数，试用期不得低于基线。另须同时满足：七天试用记录齐全、至少 **5 天** 完成规划闭环、错误或未经确认业务变更 **0 次**。逐日列出采纳/修改/拒绝、额外维护负担、同步异常和阻塞，不能仅凭一个总分宣称可用。

若人工基线规划耗时已经接近零，在看试用结果前先在 COL-24 固定“接近零”的判据、替代负担指标、计算方法和通过阈值；不能事后为通过而换指标。任一关键数据未知、候选版本跨段、或 G3 未形成有效候选时，G4 结论保持“证据不足”，并写出补采或修复后的新窗口。单人七天结果只支持此人的试用判断。

最终在 COL-24 关联候选 SHA、协议冻结记录、私有原始证据的索引、去标识逐日汇总、计算过程和用户验收结论；完成七天记录与验收后再考虑将 issue 标记 Done。
