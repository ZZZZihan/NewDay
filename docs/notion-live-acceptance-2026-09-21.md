## 真实验收发现并修复的问题

### OAuth Worker 与官方 API 版本

首次真实 token exchange 暴露两个运行环境差异：Worker 的 `fetch` 不接受 `redirect: "error"`，且 token 请求需要与候选固定的 `Notion-Version: 2026-03-11` 一致。Worker 已改为手动重定向模式、显式版本头和不含凭据的诊断日志；真实 claim、ack 和 refresh 随后成功。

### Notion 页面链接域名

真实 API 返回 `https://app.notion.com/...`，原契约只接受 `notion.so`。契约现接受精确的 `app.notion.com`、`notion.so` 及其子域，仍拒绝 HTTP 和相似域名；已增加窄范围合同测试。

### 重新授权后的安全恢复

重新授权只恢复本机凭据，不能自动把已有映射改回可发送状态。新增 `POST .../structure/reconnect`：它只读核对根页面、四张表和四个 relation 的记录、远端身份、父级、字段与属性 ID；9 项全部一致且核对期间数据、结构、授权都未变化时，才把连接由 `disconnected` 改为 `active`。权限不足或任一不一致继续保持断开，不调用远端 POST/PATCH。前端为该状态提供“核对并重新连接”，避免用“继续初始化”重放已有结构。

验收期间一次环境定位命令意外把本机凭据加密密钥写入终端输出。该值随即按泄露处理：在保持凭据内容不变的前提下，以新随机 32 字节密钥重新封装凭据库中的密文，更新本机私有环境文件，并用新密钥验证现有凭据可解密。旧密钥不再使用；轮换过程未把 access token、refresh token 或新密钥写入仓库与验收摘要。

### 停用规则后关系字段被隐藏

规则页使用 `in_trash: true` 停用后，真实 Tasks 查询会保留 `Occurrence Key`，但隐藏指向已回收规则的 relation。旧实现把它当成“不完整实例身份”并使整表扫描失败。修复只在以下条件同时满足时沿用旧身份：任务已有经过验证的映射、Occurrence Key 未变、原规则映射已经 archived。活动规则缺少关系时仍失败关闭。修复后真实全表扫描返回 200，规则 archived、series disabled、两个实例及远端页均保留。
