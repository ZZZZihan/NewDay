# Notion 一次性任务写回候选（COL-37）

本说明记录 COL-37 的本地候选行为。本轮测试使用假 Notion 传输和独立 SQLite；未执行公共 OAuth Worker 部署，也未在隔离 Notion 工作区发起实际读写。真实使用前须完成 COL-37/COL-39 的隔离工作区验收。

## 使用路径

1. 完成授权、结构初始化和首次完整扫描，确认「Notion 连接」里的结构为“就绪”、任务扫描有成功时间。
2. 在今日快速添加表单的「保存位置」选择一个 Notion 工作区，再提交一次性任务。留空则只保存本机任务；已有本地任务不会自动迁移。
3. 联动任务可在今日列表或任务总表修改标题、日期、完成状态；备注和今日重点仅保存在 NewDay。归属、重复规则和删除操作在 Notion 处理。未安排日期的联动任务可在任务总表安排日期。
4. 本机 API 每 30 秒尝试发送待处理操作；「Notion 连接」可刷新状态或手动发送。完整读取每 60 秒轮询，也可手动触发。未解决的待发送或未知操作会阻止远端扫描覆盖本地任务。

预读失败进入 `preflight_read` 暂停时，快速添加仍显示已完成首次扫描的联动工作区，「恢复发送」按钮仍可用；若此时任务扫描被待发送操作打断并记录本地冲突，已确认的首次扫描资格不会丢失。归档的联动任务须在 Notion 恢复后刷新，NewDay 不显示无法执行的本地修改按钮。

新建联动任务的本地任务、稳定 `NewDay Key` 映射和待发送操作在同一 SQLite 事务提交。它不会提供本地删除式撤销；已关联任务的标题、日期和完成状态修改可在现有撤销窗口内提交相反意图。外部 HTTP 请求在本地提交之后执行，不会阻塞任务事务。

## 状态与恢复

| 状态 | 意义 | 操作 |
| --- | --- | --- |
| `pending` | 本地意图已保存，尚未确认远端写入 | 等待轮询，或点击「发送待同步任务」 |
| `sending` | 尝试已持久记录，可能正在访问 Notion | 等待读回；不要通过新建页处理 |
| `confirmed` | 已读回目标页面和共享字段 | 可刷新扫描检查显示与归属 |
| `superseded` | 较新的本地意图取代了未发送的旧意图 | 查看后续操作状态 |
| `paused` 且原因为 `preflight_read` | 远端预读失败，尚未发出写请求 | 本机 API 仍运行时可继续保存联动新任务和修改，操作留在 outbox；检查连接或限流后，点「恢复发送」再重试 |
| `paused` 且原因为 `manual` | 用户已对已就绪工作区建立持久同步栅栏 | 自动读取和新发送停止；检查已开始的 `sending` 后，明确点击「恢复发送」 |
| `paused_unknown` 且操作为 `unknown` | 请求可能已经在 Notion 生效，但结果未确认 | 点「只读核对」；系统不会自动重发。若仍未知，保留暂停并人工核对远端页面、稳定键和字段 |
| `quarantined` 或 `paused_after_restore` | 备份恢复或数据集更换隔离了旧操作 | 保留备份和操作 ID，核对远端后另行处理；写回入口不自动解除隔离 |

恢复前本机未结算的发送与导入备份中未完成的 outbox 都保留在 `restoreQuarantine`，后者在当前 outbox 中仍显示为 `quarantined`，不会重放。`GET /api/notion/connections/:workspaceId/sync` 按工作区列出来源、旧数据集标识、操作 ID、原状态、尝试次数、任务 ID、数据源、远端页面 ID 或稳定键、原意图及隔离时间；连接面板显示这些线索。旧版备份可能没有来源标记。每项可经 `POST /api/notion/connections/:workspaceId/sync/restore/:operationId/reconcile`（请求体含 `sourceEpoch`）只读核对。已知远端页面按 ID 读取，未知页面按稳定键完成分页搜索；结果及远端字段连同读取前的时间保存为 `latestReview`，随业务 JSON 备份导出。同一数据库再次导入相同隔离操作时保留时间较新的观察，时间相同则保留现有观察；并发读取不会覆盖其开始后另一次已保存的观察。同一标识若对应不同原意图或已知远端页面，导入整体回滚。未观察到页面不证明旧请求没有成功，观察到一致值也不能证明之后不会变化。当前 outbox 为空不表示这批旧操作已结算。出现恢复隔离记录时，连接面板不提供联动新建或「恢复发送」，服务端也拒绝新发送。操作人应结合原备份和远端页面逐项记录核对结果；此候选不提供解除隔离入口。

发送前读取远端共同基准；不同字段可合并，同一字段冲突以 Notion 值为准，并在连接面板显示基准、本机、Notion 三方值。只 PATCH 发生变化的共享字段，再读回精确值。Notion 的完成勾选没有实际完成时间，远端首次完成在 NewDay 中保留未知时间。

## 目前的边界

- 固定 `Notion-Version: 2026-03-11`，SDK 自动重试关闭。稳定键搜索结果不完整或出现重复页时暂停，不创建第二页。远端预读失败转为显式重试；写请求结果不明转为只读核对。写入预检先确认 Rules 数据源仍可读取，避免权限撤销时把隐藏的规则关系当作一次性任务。
- 当前协议没有经过真实隔离工作区证明的条件写入。写前读、按字段 PATCH、写后读可以检测一部分冲突，不能承诺任意并发下零覆盖。429/529 写前预读错误会保存 `Retry-After` 截止时间，截止前拒绝恢复；到期后仍须人工点击，未自动重试。真实响应与退避解析仍需在隔离工作区验证。
- 尚未提供恢复隔离操作的一键核销。堆叠的 COL-38 候选增加了 Notion 规则读取和实例字段写回；规则本身仍只在 Notion 编辑，真实工作区往返尚未验收。联动任务删除与归属修改留在 Notion；本机不自动删除远端页面。
- 本地测试覆盖事务回滚、往返、撤销、响应丢失、旧意图取代、空日期、冲突和读写交错。实际 OAuth、Notion schema、限流、回收站和并发响应需在隔离工作区复核，不能由假传输测试代替。
