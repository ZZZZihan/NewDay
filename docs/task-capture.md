# 对话提取与待办创建（COL-48）

本功能让用户从 NewDay 内的自然语言输入或粘贴的外部聊天记录，一次提取并保存一个或多个待办。原来的今日重点建议继续独立使用，不改变已有重点选择语义。

## 交互与日期

“直接告诉我”的“发送并加入待办”按钮明确授权本次新增；全部草稿具有有效日期且无需复核时，后端直接创建。“粘贴已有对话”仅提取草稿，用户可修改、勾选，再批量加入。空结果不写任务，缺失日期不自动填今天。模型应排除否定、取消、假设以及别人的安排；来源原文必须能在本次输入中找到。

每次最多 20 条一次性任务，使用用户已保存的规划时区固定相对日期的基准。跨日、时区更改或替换数据集后的未执行结果需要重新提取。任务仅支持开始/结束日期；时分放在备注，不设置提醒。重复需求需要复核，不会由对话自动建立重复规则。需在既有任务编辑器建立重复规则。

本功能不自动指定 Notion 工作区，不修改已有任务，不自动设定今日重点。批量创建没有独立的一键撤销入口；创建后的任务可用已有编辑和删除功能管理。

## 接口和执行边界

共享合同：[task-capture.ts](../packages/core/src/contracts/task-capture.ts)。模型只能返回结构化草稿；任务 ID、执行请求与持久回执由服务端掌握。

| 接口 | 行为 |
| --- | --- |
| `GET /api/agent/captures/status` | 模型配置状态与模型标识 |
| `POST /api/agent/captures` | `{requestId, mode, text}`；建立运行，返回 `202`，模型在数据库事务外执行 |
| `GET /api/agent/captures/:id` | 查询原运行；`captureId` 等于原 `requestId`，响应丢失也可恢复 |
| `POST /api/agent/captures/:id/apply` | `{operationId, tasks}`；验证草稿关联和日期后原子创建勾选项目，返回带回执的运行 |
| `POST /api/agent/captures/:id/cancel` | 中断尚未执行的运行，迟到模型结果不得再写入 |

同一请求 ID 的相同请求恢复原运行，不重复调用模型；不同内容使用相同 ID 会冲突。同一执行 ID 的相同内容返回原结果，改动内容则冲突。一次运行完成创建后，换执行 ID 也不能再次添加。执行前验证数据集、时区与日期；事务内同时写入全部任务、运行状态及回执。任一步失败回滚整批。

浏览器用 `sessionStorage` 保存本标签页当前输入、运行标识和待确认的精确提交，刷新后查询原请求。存储不可用或关闭标签页后的恢复不作保证。服务端保存记录用于恢复与核对；API 重启不会自动重放未完成的模型调用。

## 模型与记录

复用 `NEWDAY_AGENT_*` 的 OpenAI compatible/DeepSeek profile 配置，默认 disabled。发送内容限于用户本次提交的文本、入口模式、规划时区与基准日期，不附带整个任务库。现有匹配任务检查发生在本机。模型响应经结构、来源原文、日期和批量数量校验后才可能执行；输出文字本身不算执行凭据。

任务数据进入现有任务 JSON 备份。对话运行和创建回执使用独立 namespace；当前 `newday-agent` v1 JSON 备份不包含这些记录，完整 SQLite 文件备份包含它们。`DELETE /api/agent/history` 清除对话文本、草稿及回执详情，保留最小请求摘要和终态防止旧请求重放，不删除已创建任务；网页标签页的会话缓存应另通过新输入/浏览器会话清理。

自动识别是否属于本人、是否已取消、相对日期等依赖模型质量。scripted provider 只在已有隔离 E2E 配置下启用；它不代表真实模型语义表现。本次工程验收与真实模型质量、合并、部署分别记录。

## 验证

必需检查为 `pnpm check`、`pnpm build`，以及 `pnpm test:e2e tests/e2e/task-capture.spec.ts tests/e2e/agent-planning.spec.ts`。浏览器测试沿用 `3100/3002` 与 `newday-e2e-*` 临时 SQLite；不能使用开发数据库执行替换导入 fixture。

检查重点为单条/多条新增、先预览后提交、缺失日期、无任务、非法模型输出、整批回滚、请求重放/冲突、响应丢失与页面恢复、取消/重启、跨日/时区/数据集变更以及清理记录后的去重。
